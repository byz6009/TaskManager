## 回滚方法（说明，未执行）

先辨别是代码问题还是浏览器存储问题。记录复现和目标提交，备份当前站点两个键的原始值；代码回滚不会恢复或清空 localStorage。

1. 先检查 git status、git diff 和目标提交 git show，保留未提交工作。工作区不干净时不要直接 reset、clean 或覆盖文件。
2. 本轮目前只有文档，确认前可按 diff 有选择地撤销本轮文档变更；不要删除原有源码或任务存储。
3. 对已经提交的变更，用户同意后优先 git revert <实际提交哈希> 生成逆向提交、保留历史。例如 git revert b2b694c 仅撤销主题轮次；撤销多个依赖轮次时按从新到旧顺序逐项审查，不机械批量运行。
4. 回滚后先点加载课程环境，再运行 npm.cmd test、npm.cmd run build，并重新做相关浏览器验收。若依赖锁文件发生变化，按 README 的课程安装流程恢复依赖。
5. 存储损坏先备份并修复该应用对应键，再刷新读取。不得使用 localStorage.clear() 清空同来源其他数据；不得以 Git reset --hard 代替问题定位。
